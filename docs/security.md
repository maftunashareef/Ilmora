## 0. Как читать документ

Каждое требование имеет номер `БЗ-<раздел>.<n>` и статус:

| Статус | Значение |
| --- | --- |
| ✅ | Выполнено в коде/инфраструктуре, указано где |
| ⚠️ | Выполнено частично или зависит от настройки на сервере |
| ❌ | Не выполнено — нужна доработка |
| 🔧 | Не код, а действие владельца/администратора (настройка, договор, процедура) |

Требования с пометкой **[до запуска]** обязательны до приёма реальных платежей и персональных данных.

Связанные документы: `docs/payments/onboarding-checklist.md` (Payme), `docs/compliance/uz-personal-data-localization.md`

## 1. Область и модель угроз

**Защищаемые активы:** деньги (платежи Payme, бухгалтерские проводки), персональные данные учеников, учителей и
сотрудников центров (ФИО, телефоны, посещаемость), учётные записи (особенно Super Admin / владелец), контент центров,
ключи и секреты сервера.

**Роли:** гость, ученик, учитель, администратор центра, Super Admin, владелец (`isOwner`). Платформа мультитенантная:
данные одной организации (tenant) и одного центра не должны быть видны другим.

**Основные угрозы:**
1. Подделка уведомлений об оплате → бесплатная активация подписки.
2. Захват аккаунта (подбор пароля/кода, кража сессии, перехват SMS, захват телефона).
3. Доступ к чужим данным (IDOR, обход изоляции центров/тенантов).
4. XSS/CSRF через веб-интерфейс.
5. Утечка секретов и персональных данных через логи, Sentry, бэкапы, git.
6. Компрометация сервера, базы, Redis, CI/CD.
7. Злоупотребления: спам SMS, перебор, перегрузка API.
